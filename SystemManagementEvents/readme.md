# Система управления мероприятиями образовательной организации

Учебный проект по теме №18.

## Назначение проекта

Система предназначена для автоматизации управления мероприятиями образовательной организации. Она позволяет создавать и публиковать мероприятия, регистрировать участников, назначать помещения, составлять программы и оформлять результаты.

## Архитектура

Документация по архитектуре находится в каталоге `docs/architecture/`.

В каталоге представлены следующие материалы:

- `architecture.md` — описание архитектурного решения.
- `ADR-001.md` — обоснование выбора архитектурного стиля.
- `diagrams.drawio` — диаграммы проекта.

Архитектура проекта предусматривает разделение серверной части и пользовательского интерфейса. Взаимодействие между ними осуществляется посредством HTTP-запросов к Web API.

## Структура решения

Решение содержит два основных проекта:

### EventsApi

Серверное приложение на ASP.NET Core Web API.

Основные компоненты:

- `Controllers/` — обработчики HTTP-запросов.
- `Data/` — интерфейс и реализация репозитория мероприятий.
- `Models/` — модели данных.
- `Program.cs` — настройка и запуск приложения.

Предоставляет следующие операции:

- Получение списка мероприятий.
- Получение мероприятия по идентификатору.
- Создание нового мероприятия.
- Удаление мероприятия.

Для документирования API используется Swagger.

### EventsClient

Настольное приложение на Windows Forms.

Основные возможности:

- Асинхронная загрузка мероприятий с сервера.
- Отображение данных в таблице.
- Создание новых мероприятий.
- Проверка корректности вводимых данных.
- Обработка ошибок подключения и ответов сервера.
- Отмена выполняемых запросов.
- Поиск мероприятий по названию и аудитории.
- Контекстные подсказки и справочная информация.

## Запуск проекта

Для запуска системы необходимо выполнить следующие действия:

1. Открыть решение в Visual Studio.
2. Убедиться, что проекты `EventsApi` и `EventsClient` включены в конфигурацию запуска.
3. Запустить решение.
4. Дождаться запуска серверного приложения и пользовательского интерфейса.

Адрес Web API:

`http://localhost:5289`

Документация API Swagger:

`http://localhost:5289/swagger`

Для работы клиентского приложения сервер должен быть запущен и доступен по указанному адресу.

## Ограничения проекта

- Размер команды: 3 человека.
- Срок разработки: 4 месяца.
- Общая трудоёмкость: 12 человеко-месяцев.

## Текущий статус разработки

На текущем этапе реализованы базовые операции управления мероприятиями через Web API и настольный клиент.

Серверная часть использует репозиторий с хранением данных в оперативной памяти. При перезапуске сервера данные возвращаются к начальному состоянию.

Дальнейшее развитие проекта предполагает расширение функциональности системы в соответствии с требованиями курсовой работы.
